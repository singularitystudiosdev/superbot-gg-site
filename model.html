superbot, the model

one name to talk to. a loop that does the work. model id: superbot

when you pick "superbot" in any app, one thing answers: superbot's agent loop, running the best model it has for the job. today that is a self-hosted GLM-5.3-Flash by default, with a claude fallback, or your own subscription when you connect one. the loop is what makes it finish in fewer steps with fewer tokens. the ledger below says exactly what is measured, what ships, and what is still a plan.

the loop

an agent loop with tools (web search, fetch, papers, repos, your MCP servers) that runs every request the same way whatever model name it arrived with. measured against the claude agent sdk on the same model: more tasks finished, fewer steps, a third of the tokens.

the models under it

default GLM-5.3-Flash, self-hosted. if that box is down, claude-sonnet-5 takes the turn. connect your own claude, chatgpt or grok and it runs on the subscription you already pay for.

where you reach it

one MCP endpoint, installed into every AI app on your machine by one line. talk to it in the chat, the phone app, or from inside any coding agent as /superbot.

the claims, with what backs them

every claim about the model gets the same row: the claim, what would prove it, and its status today. a dashed pill is a slot: we intend to make it true and we are not saying it yet.

learns what it lacksa missing tool becomes a new one
shipped, human in the loop. a request nothing can serve is logged as a miss, a worker drafts an adapter for it, and a person promotes the draft after its load check passes. 33 adapters live today, all hand-promoted; the automatic drafts have not yet produced a promoted one.
shipped · gated
runs tools in parallel, hands work to helpers"native agent swarms"
partly. tool calls in one step run in parallel, a research scout runs alongside the main loop, and batch requests fan out. the loop's own subagent tool (a child loop per named helper) exists upstream and is not switched on in superbot yet.
partly · subagents off
answers with today's web, not last year's"a constantly updated dataset"
shipped, as live tools rather than training. the loop searches the web, fetches pages, reads papers and repos on every request that needs it, and stamps what it learned with the date it was retrieved. no custom training corpus exists.
shipped · live retrieval
cheaper and faster than frontier models at equal qualityfable 5, fable 5.1 and the rest
no ledger yet. what would back it: the same task set run through superbot and through each frontier model, with quality, wall-clock and cost per task, published with its raw rows. the only cross-model run today is a prompt A/B on fable 5.1 inside the loop, not superbot against fable.

fine-tuned for no-nonsense agentic work"a custom rust harness"
no fine-tune exists. the behaviour comes from a fixed system prompt, a guard that fences untrusted input, a read-only tool policy, and the loop itself, which is written in typescript. if a fine-tuned checkpoint ships, this row gets its eval.

works on a task for as long as it takes, no hand-holdingunbounded runs
capped today. a hosted turn runs up to six steps and comes back as a miss rather than spinning; a research scout gets 150 seconds beside it. lifting the cap is a product decision with a cost meter behind it, not a copy change.
